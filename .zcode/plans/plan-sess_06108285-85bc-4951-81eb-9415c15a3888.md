АГЕНТ-ЭКСПЕРТ С ДОСТУПОМ К ДОКУМЕНТУ (v1.11.0)

ДИАГНОЗ (подтверждён разведкой): сейчас контекст = только выделение (ViewCursor.getString(); функция чтения всего документа в коде мёртвая), без выделения модель получает «(no selection)» — отсюда просьбы «скопируйте текст в чат». Tool calling в провайдерах отсутствует полностью. В Calc читается ≤200 ячеек выделения без формул/имён листов; запись — одна ячейка setString.

ПОДХОД (подтверждён вами): агентный цикл с инструментами; первая итерация = Calc-эксперт + Writer; правки применяются сразу (откат Ctrl+Z — каждая операция обычная UNO-правка). Провайдеры без function calling продолжают работать в обычном режиме.

1) НОВЫЙ МОДУЛЬ lo_ai/document_tools.py — «руки» агента
Реестр инструментов: имя, описание для модели, JSON-схема параметров, функция(model, args)→строка (результат обрезается до ~4000 симв.). Calc: calc_info (листы + used ranges), read_range (значения + опц. формулы, лимит ячеек), write_range (setDataArray), set_formula, sort_range, format_range (жирный/цвет/числовой формат), create_chart (column/bar/line/pie/area/scatter через TableCharts.addNewByName), create_pivot (сводная через DataPilotTables: строчные/столбцовые поля, данные, функция агрегации), find_replace. Writer: writer_info, read_document (весь текст с маркерами абзацев), read_selection, replace_selection, insert_at_cursor, find_replace. Каждая операция валидирует аргументы; ошибка модели возвращается ТЕКСТОМ (модель сама исправится).

2) ПРОВАЙДЕРЫ: tools для api_style="openai" (14 из 17 пресетов, вкл. ваш Z.ai GLM)
base.py: новый AssistantTurn{content, tool_calls:[{id,name,args}]} + chat_with_tools(messages, tools, cancel) (нестриминговый — надёжнее для цикла; стриминг обычного чата не трогаем). openai_compat.py: payload += tools/tool_choice:auto; парс message.tool_calls; обратные сообщения: assistant с tool_calls + role:"tool" с tool_call_id. anthropic/responses — в следующей итерации (fallback: обычный чат).

3) АГЕНТНЫЙ ЦИКЛ — новый lo_ai/agent.py
run_agent(model, settings, user_message, history, on_step, cancel): системный промпт агента (роль + правила + тип документа из document_bridge) → до agent_max_steps (12, конфиг): вызов модели → tool_calls? → исполнение через document_tools (UNO-вызовы из рабочего потока — только через pump, добавлю синхронный pump.call(fn) с ожиданием) → результаты в сообщения → снова модель; без tool_calls → финальный ответ. on_step печатает в чат «⚙ read_range Данные!A1:F30…» и статус.

4) ФИКС КОНТЕКСТА (и для обычного режима)
Writer: без выделения — текст всего документа (мёртвый _writer_document_text оживает), cap context_chars; Calc: used range активного листа + имена листов компактным превью.

5) UI/КОНФИГ
Галочка → «Работать с документом (агент)» (config agent_enabled, default True); agent_max_steps=12. on_send: агент-режим + провайдер с tools → run_agent, иначе текущий путь. i18n RU/EN/ZH для шагов.

6) ТЕСТЫ И ВЕРИФИКАЦИЯ
Новый tests/test_agent.py на хосте (без UNO): фейковый провайдер со скриптованными tool_calls + фейковые инструменты → полный цикл (2 шага → финал), лимит шагов, кривые аргументы. Плюс py_compile, test_static, существующие тесты провайдеров. Сборка + установка при закрытом LO + grep верификация развёрнутого пакета. Финал — ваш e2e в живом LO с реальным ключом: «построй сводную по листу…», «график по столбцам B:D», «исправь абзац…» — этот тест заодно закроет вечно-непроверенный блок обычного чата.

РИСКИ: формат tools у z.ai-гейтвея (стандартный OpenAI — проверить живым тестом; при несовместимости вернём диагностику в лог); UNO-вызовы через pump (дедлок исключён — главный поток живёт); кривые аргументы модели → валидация + текст ошибки модели; DataPilot API многословен (реализация, не риск).
